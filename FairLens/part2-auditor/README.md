# AI Quality Assurance Auditor

A fairness auditor for bank loan-approval AI models, built for the AI QA Auditor hackathon prototype.  
It treats the bank model as a **black box**: generates test applicants, sends them to the model, and analyses the returned decisions for hidden demographic bias.

---

## Project Structure

```
├── requirements.txt

│   ├── data_prep.py             ← HMDA loading and filtering

│   ├── ingest.py                ← load and validate bank results (Module 2)

```

## Quick Start

### 1 — Install dependencies

```bash
pip install -r requirements.txt
```

### 2 — Place the HMDA data

Copy your **2018 Los Angeles County HMDA LAR CSV** to `data/hmda_la_2018_lar.csv`  
(or update `hmda_path` in `config.yaml`).

### 3 — Place Part 1's trained model

Copy `bank_model.joblib` and `feature_list.json` from Part 1 into `models/`.  
If they are absent, `bank_connector.py` falls back to `fake_bank_model.py` automatically.

### 4 — Generate test applicants

```bash
python main.py generate
```

Produces two files:
- `data/applications_for_bank.csv` — send this to the bank's scoring system  
- `data/audit_key.csv` — keep this; it contains demographics the auditor needs

### 5 — Score applicants (bank model)

```bash
python main.py score
```

Loads Part 1's model (or the fake model fallback) and writes `data/bank_results.csv`  
(`case_id`, `decision`, `probability`).

### 6 — Run the full audit

```bash
python main.py audit --results data/bank_results.csv
```

Runs ingest → fairness analysis → report generation.  
Outputs land in `output/`.

### 7 — Run all steps at once

```bash
python main.py run-all
```

## LLM Credentials (IBM Granite via watsonx.ai)

Set these environment variables before running `main.py audit`:

```bash
export WATSONX_API_KEY="your-api-key"
export WATSONX_PROJECT_ID="your-project-id"
export WATSONX_URL="https://us-south.ml.cloud.ibm.com"
```

If any variable is missing the report falls back to a plain-text template automatically — the demo will never break due to missing credentials.

## Key Design Decisions

| Decision | Reason |
|---|---|
| Two CSVs (applications + audit_key) | Simulates the real-world separation: the bank never sees demographics; the auditor never loses them |
| Census-tract fields copied together | Prevents geographic inconsistencies in generated applicants |
| `class_weight="balanced"` RF model | Denials are ~15–25 % of records; imbalance handling is critical for meaningful fairness metrics |
| Template fallback for LLM report | Demo reliability: the report section must work even with no internet/credentials |
| Each audit function callable independently | Enables Streamlit integration and future watsonx Orchestrate tool wrapping |

## Fairness Thresholds

| Metric | Flag threshold | Severity |
|---|---|---|
| Disparate impact ratio | < 0.80 (four-fifths rule) | low |
| Disparate impact ratio | < 0.75 | medium |
| Disparate impact ratio | < 0.60 | high |
| Proxy feature AUC | > 0.65 | flagged |

All thresholds are configurable in `config.yaml`.
